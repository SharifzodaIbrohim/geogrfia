# P1.1 — Authentication architecture (session cookies)

## Target flow

```
Google
  → Google verifies identity (ID token)
  → Backend verifies Google token (google-auth)
  → Backend creates signed session (JWT)
  → Set-Cookie HttpOnly Secure SameSite=Lax Path=/
```

Admin login uses the same pattern with a **separate** cookie.

## Cookie names

| Role | Production (HTTPS) | Local HTTP |
|------|--------------------|------------|
| User / Gmail | `__Host-geografia_session` | `geografia_session` |
| Admin | `__Host-geografia_admin` | `geografia_admin` |

`__Host-` requires: `Secure`, `Path=/`, no `Domain` attribute.

## Flags

- `HttpOnly` — not readable from JavaScript
- `Secure` — HTTPS only (production)
- `SameSite=Lax` — CSRF mitigation for top-level navigations
- `Path=/`

## Frontend

All authenticated `fetch` calls use `credentials: 'include'`.

Do **not** store session credentials in `localStorage`.
Display-only profile (`geo_user`, `geo_admin_user`) may remain local.

## Endpoints

| Method | Path | Effect |
|--------|------|--------|
| POST | `/api/auth/google` | Verify Google + set user cookie |
| POST | `/api/auth/logout` | Clear user cookie |
| GET | `/api/auth/me` | Current user from cookie |
| POST | `/api/admin/login` | Set admin cookie |
| POST | `/api/admin/logout` | Clear admin cookie |
| GET | `/api/admin/me` | Current admin from cookie |

Legacy `Authorization: Bearer` / `X-Admin-Token` still accepted during transition.
